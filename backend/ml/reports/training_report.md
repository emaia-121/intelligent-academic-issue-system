# Academic Issue Classifier -- Training Report

This report documents how `ml/train_classifier.py` produced the exported classifier in `ml/models/`. It is written for a developer who did not run the training themselves and needs to understand or maintain the pipeline.

## 1. Dataset

- Source file: `ml/dataset/academic_issue_dataset.csv`
- Total labelled examples: **1500**
- Number of categories: **12** (fixed list, no categories invented)
- Generated by `ml/generate_dataset.py`: a template-and-slot synthetic generator (20-30 hand-authored sentence skeletons per category, combined with randomized course codes, sessions, levels, departments, optional tone openers/closers, and light informal text substitutions). All 1,500 rows are verified unique strings -- duplicates are rejected and regenerated at creation time.

## 2. Train/Test Split

- Target ratio: 80/20, stratified by category.
- **Grouped by sentence template within each category**, not a plain row-level split: `generate_dataset.py` records which of the ~20-30 hand-authored skeletons produced each row (`template_id`), and `train_classifier.py::split_dataset` splits each category's *templates* 80/20 (`sklearn.model_selection.train_test_split(..., random_state=42)` applied to the template ID list) before assigning every row to whichever side its template landed on.
- This was a deliberate change from a naive per-row stratified split. A first pass using a plain row-level stratified split let the same skeleton (e.g. *"My {code} result has not appeared since {session}."*) appear on both sides with only a course code swapped, and every model scored 99-100% test accuracy -- a sign the test set wasn't actually novel to the model, just superficially reworded. Grouping by template means every test-set sentence uses phrasing the model never saw during training, which is what the task means by "the classifier should learn concepts rather than memorize phrases." The resulting scores (Section 6) are lower but meaningfully honest.
- Training examples: **1163**
- Test examples: **337**
- `random_state=42` is fixed throughout the pipeline (split, cross-validation, and every model that accepts a `random_state`) so results are reproducible.

## 3. Preprocessing

Implemented in `ml/preprocessing.py`. Applied identically to every example before vectorization:

1. **Course-code normalization** (before lowercasing): `"CSC 311"` -> `"CSC311"`, so spaced and unspaced course-code mentions always tokenize identically instead of the spaced form splitting into two diluted tokens.
2. **Lowercasing**: case carries no classification signal here and keeps the vocabulary compact.
3. **Whitespace normalization**: repeated spaces/newlines collapse to one space; leading/trailing whitespace stripped.
4. **No stemming/lemmatization**: course codes and domain abbreviations (GST, NYSC, JAMB, CGPA, CSC311, ...) are exactly the signal the classifier should keep intact, and stemming risks mangling them or collapsing meaningfully distinct words. Skipped per the task's own guidance to avoid aggressive stemming unless justified -- no evaluation here showed a benefit.
5. **Stopword removal**: not hardcoded. Evaluated explicitly (see Section 4) as part of the TF-IDF configuration search rather than assumed.

## 4. Feature Extraction (TF-IDF)

`ml/evaluation.py::select_best_vectorizer_config` cross-validates every candidate TF-IDF configuration using a fixed Logistic Regression probe model and 5-fold stratified cross-validation, scored on mean macro-F1 -- all on the **training split only**, so the held-out test set never influences this choice. Candidates varied unigrams vs. unigrams+bigrams, stopword removal on/off, and `min_df` of 2 vs. 3 (`max_df` fixed at 0.9).

## 5. Models Trained

All four required classical models, trained on the same TF-IDF features (see `ml/model_config.py` for exact hyperparameters and the reasoning behind each):
1. Multinomial Naive Bayes
2. Logistic Regression
3. Linear Support Vector Machine (LinearSVC)
4. Random Forest

## 7. Selected Model

**Random Forest** was selected automatically -- the pipeline sorts all four models by macro-F1 on the test set and picks the top row; no model is assumed best in advance.

- Test accuracy: 89.02%
- Test macro precision: 90.57%
- Test macro recall: 88.79%
- Test macro F1: 88.80%

Macro-F1 was used as the ranking metric (rather than plain accuracy) because it weights every one of the 12 categories equally -- important for a routing system where a rarely-seen category being misclassified is just as costly as a common one being misclassified, even on this class-balanced dataset.

## 8. Export

- Trained classifier: `ml/models/classifier.pkl` (joblib)
- Fitted TF-IDF vectorizer: `ml/models/vectorizer.pkl` (joblib)
- Category label list: `ml/models/label_classes.json`
- Run metadata (chosen model, vectorizer config, dataset size, timestamp): `ml/models/metadata.json`

To use the classifier later (not part of this task -- integration into Django views is intentionally out of scope), load both artifacts and apply the same preprocessing before vectorizing new text:

```python
import joblib
from ml.preprocessing import clean_text

classifier = joblib.load('ml/models/classifier.pkl')
vectorizer = joblib.load('ml/models/vectorizer.pkl')

text = clean_text(raw_issue_description)
predicted_category = classifier.predict(vectorizer.transform([text]))[0]
```
